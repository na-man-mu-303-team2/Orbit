스타일 상속 해석 · 세 가지 Render Mode

01스타일 상속 해석

텍스트 스타일은 한 XML 노드에 있지 않고 여러 계층에 분산됩니다. 아래 계층을 함께 해석해 최종 속성을 계산합니다.

Theme→Master→Layout→Slide→Paragraph→Run
  • 글꼴 family·numeric weight 정규화 (예: Pretendard)
  • 글자 크기·색·줄간격·자간·내부 여백
  • 자동 글자 크기 조정, 문단·run 단위 override

02세 가지 Render Mode

  • Editable — 지원 텍스트·도형을 Deck 요소로 변환, 위치·크기·스타일 편집
  • Hybrid — 가능한 요소는 편집 가능하게, 정확히 못 바꾸는 부분은 원본 표현
  • Snapshot — 원본 렌더 그대로 표시, selection·mutation 차단
데이터 보존을 위해 element tree는 남기되, 사용자가 편집 가능하다고 오해하지 않도록 조작을 차단합니다.

03발표자 노트 보존

파일명 규칙이 아니라 PresentationML relationship을 따라 연결합니다.

Slide→rel→Notes Slide→rel→Notes Master
  • 전체 notes page 재생성 없이 body만 targeted update
  • notes master·이미지·footer·page number·media 유지

04품질 판정 (Fail-closed)

  • pixel 기준 충분 → editable 유지
  • 기준 이하·지원 불가 객체 → hybrid/snapshot 권장
  • unresolved asset·심각한 외형 차이 → hard failure
  • 측정 안 한 품질 → 성공값 아닌 not-evaluated
증명하지 못한 품질을 "편집 성공"으로 처리하지 않는다. 변환된 듯 보이지만 실제 데이터가 손실되는 상황을 막습니다.

  • NFC·NFD, CRLF·LF, 연속 공백, 말줄임표 정규화
  • 한·중·일 문장부호, code point offset 기준

02Lexical Evidence Accumulator

# 대본 민트의 상쾌함과 초콜릿의 풍부함이 서로를 보완합니다. Partial 1: 민트의 상쾌함과 Partial 2: 민트의 상쾌함과 초콜릿의 Partial 3: 민트의 상쾌함과 초콜릿의 풍부함이 Final: … 서로 보완합니다 ← 여기서 commit

Partial에서는 evidence만 쌓고, 같은 단어를 원문 등장 횟수 이상 과대 계산하지 않습니다.

기술적 챌린지 ② · 상세· 구현 2

Commit State Machine · E5 제한 · 생략 복구

03Commit State Machine

tracking→근거→candidate→Final/Pause→commit→next tracking
  • 같은 final 재전달돼도 연속 완료 안 됨
  • 늦게 도착한 이전 문장 STT 무시
  • 수동 다음·이전·reset과 충돌 없음

04Final Deduplication

utteranceId·resultRevision 우선, 없으면 시간창+digest로 동일 final 판정.

05E5의 역할 제한

E5는 문장 완료를 직접 결정하지 않습니다. 최소 어휘 근거가 관측된 경우에만 보조 evidence로 사용해, 표현을 바꿔도 따라가되 무관한 발화가 임베딩상 가깝다는 이유로 완료되지 않게 합니다.

06문장 생략 복구

Current·+1·+2·+3
건너뛴 문장은 skipped로 기록·미완료, 실제 발화한 대상 문장만 final/pause에서 commit.

두 챌린지의 연결
PPTX 가져오기에서는 품질을 증명할 수 없는 결과를 편집 가능하다고 처리하지 않았고, 실시간 프롬프터에서도 충분한 발화 근거가 없으면 문장을 완료하지 않도록 같은 원칙을 적용했습니다.
공통 설계 원칙확실하지 않은 결과를 성공으로 처리하지 않는다
